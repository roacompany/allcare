# 시리로 모든 기록 — 설계

- 작성: 2026-08-23
- 계기: PO — "시리가 모든 기록을 할 수 있게 개선해야할 것 같아. 소변 이런것도 기록이 안되는 것 같은데요."
- 선행: v2.8.9(#75) 시리 수유 기록 — 2026-08-22 출시·라이브
- 배포 대상: **v2.8.10** (2.8.9 train closed · ASC 최고 빌드 105 → 다음 TF ≥106)

---

## 0. PO 요약 (쉬운 말로)

앱의 기록 종류는 12가지인데 시리로 되는 건 3가지(모유·분유·모유(병))뿐입니다. **9가지가 안 됩니다.**

이 문서는 **12가지 전부**를 시리로 되게 만드는 계획입니다.

- 소변·대변·목욕·이유식·간식은 **말 한마디로** 저장됩니다(앱에서도 한 번 누르면 끝나는 것들입니다).
- 유축·체온은 **숫자를 되묻습니다**(분유가 지금 그러는 것과 같습니다).
- 수면은 **"잠들었어" / "깼어"** 두 마디입니다. 앱에 이미 있는 수면 타이머를 시리가 만지는 것이라, 앱에서 한 것과 똑같이 남습니다.
- 손님이 말할 문구를 제가 12줄 적는 게 아니라, **「베이비케어에 ⟨종류⟩ 기록」 한 줄**과 종류 목록만 줍니다.
- **데이터는 하나도 안 바뀝니다.** 저장 규칙·통계·유축 재고·병원 리포트 전부 지금 것 그대로 씁니다.

## 1. 문제

### 1.1 실측 — 무엇이 되고 무엇이 안 되나

기록 런처(`RecordTile.launcherSections`) 12타일 기준:

| | 타일 | 시리 |
|---|---|---|
| 자주 | 모유 · 분유 · 모유(병) | ✅ 됨 |
| 자주 | 수면 · 소변 · 대변 | ❌ |
| 가끔 | 이유식 · 간식 · 체온 · 투약 · 목욕 · 유축 | ❌ |

**3/12만 됨.** 9종이 시리에서 막혀 있다.

### 1.2 왜 이렇게 됐나

`#75` 는 수유 하나만 겨냥해 만들었고, 그래서 뼈대 이름부터 수유 전용이다:

- `SiriFeedingRequest` / `SiriFeedingPlanner` / `SiriFeedingRecorder` / `RecordFeedingIntent` / `SiriFeedingKindOption`

전 종류로 넓히려면 이 뼈대를 **기록 일반**으로 다시 세워야 한다. 이름만 바꾸는 일이 아니라, "이 기록은 무엇을 되물어야 하나"라는 판정이 새로 필요하다.

### 1.3 곁가지로 드러난 것 — 「무엇을 물어야 하나」 판정이 다섯 군데

전 종류로 넓히면 **되묻기 판정**이 필요한데, 지금 그 성격의 판정이 흩어져 있다:

| 판정 | 실제 사용처 | 상태 |
|---|---|---|
| `ActivityDraftBuilder` | 저장 시 실제 검증 | **진짜 진실** |
| `RecordEntryRule.mode(for:)` | 앱 화면(홈·런처·첫기록 가이드) | 살아 있음 |
| `SiriFeedingRequest.Kind.requiresAmount` | 시리 전용 | 살아 있음 |
| `ActivityType.needsAmount` | **테스트만** | 프로덕션 사용 0 |
| `ActivityType.needsQuickInput` | **테스트만** | `RecordEntryRule` 이 대체함 · 사용 0 |

같은 질문에 답이 다섯 군데 있고 그중 둘은 이미 죽었다. 여기에 시리용을 하나 더 만들면 여섯이 된다.
→ 이 작업의 일부로 **하나로 모으고 죽은 둘을 정리**한다. (없앨 수 없는 건 `ActivityDraftBuilder` 뿐이다 — 그게 실제 저장을 막는 자리다.)

## 2. 목표 · 비목표

### 목표
1. 기록 런처 12종 **전부** 시리로 기록된다.
2. 저장 규칙·통계·재고·병원 리포트 계약은 **하나도 안 바뀐다**(`ActivityDraftBuilder` 재사용).
3. 손님이 단축어 앱에서 아무것도 만들지 않아도 바로 된다(App Shortcuts).
4. 출처(`source = .siri`)가 전 종류에서 남는다.
5. 되묻기 판정이 **하나**이고, 저장 검증과 어긋나면 게이트가 잡는다.

### 비목표 (이번에 안 함)
- 성장(키·몸무게)·일기·접종 — Activity 가 아니라 별도 컬렉션. 범위 밖.
- 시리로 **아기 고르기** — 앱에서 고른 아기에만 기록(현행 제약 유지).
- 시리로 **조회**("오늘 몇 번 먹었어?") — 기록만.
- 시리로 **수정·삭제** — 잘못 말했을 때의 되돌리기는 앱에서.
- 자유 발화 해석(아래 §3.3) — 되묻기 한 번이 붙어 밤중 한 손 원칙과 어긋난다.
- 소변+대변(`diaperBoth`) — 런처에서 이미 뺀 타일(옛 기록 표시용 enum 만 유지). 시리에도 안 넣는다.

## 3. 플랫폼 제약 (실측)

### 3.1 App Shortcuts 는 앱당 10개
애플 제한. 지금 3개 사용. 12종을 하나씩 넣으면 넘친다.
→ **문구 안에 종류를 변수로** 두면(`\(\.$kind)`) 한 자리가 여러 값을 받는다. 배포 타깃이 iOS 17 이라 사용 가능.

### 3.2 문구 총량 1,000개 — 파라미터 옵션 하나가 문구 하나로 계산
이번 설계 사용량 = **54개**(§4.2). 여유 충분.

### 3.3 「AI가 알아서」는 우리 분야에 안 열려 있다
애플이 시리에게 자연어를 맡기는 길(App schema domains)의 실제 목록:

- 시리 자연어: 음악 · 캘린더 · 카메라 · 시계 · 파일 · 메일 · 지도 · 메시지 · 메모 · 전화 · 사진 · 미리알림 · 검색
- 단축어 앱 전용: 책 · 브라우저 · 일기 · 프레젠테이션 · 문서뷰어 · 스프레드시트 · 화이트보드 · 워드
- **육아 · 건강 · 기록: 없음**

가장 가까운 '메모'·'일기'에 얹으면 기록이 **글**로 저장돼 수유량 합계·유축 재고·병원 리포트가 전부 어긋난다. → 채택하지 않는다.

자유 발화(`String` 파라미터)를 받는 길은 있으나 시리가 **되묻기 한 번**을 강제한다("무엇을 기록할까요?"). 「소변 기록」 한마디보다 나쁘므로 비목표.

## 4. 설계

### 4.1 뼈대 — 수유 전용을 기록 일반으로

판정은 순수 함수, 부수효과는 얇은 껍데기. #75 의 구조를 그대로 이어받되 이름과 범위를 넓힌다.

| 지금 | 바뀜 | 하는 일 |
|---|---|---|
| `SiriRecordContext` | **그대로** | 어디에 기록하나(소유자 경로·아기) |
| `SiriFeedingRequest` | → `SiriRecordRequest` | 무엇을 기록하나 → `ActivityDraft` |
| `SiriFeedingPlanner` | → `SiriRecordPlanner` | 판정(되묻기·거절·문구) |
| `SiriFeedingRecorder` | → `SiriRecordRecorder` | 저장(오프라인 큐 + 계측) |
| — | **`SiriPromptPolicy` (신규)** | 이 종류는 무엇을 되물어야 하나 |
| — | **`RunningTimerStore` (신규)** | 무슨 타이머가 돌고 있나 (§4.4) — 수유 타이머도 담으므로 `Sleep…` 이라 부르지 않는다 |

`ActivityDraftBuilder` 는 **손대지 않는다.** 저장 규칙의 유일한 주인이다.

### 4.2 시리 명령 표면

`AppShortcut` 8자리 (한도 10):

| # | 명령 | 문구 예 |
|---|---|---|
| 1~5 | 프리셋 — 모유 · 분유 · 모유(병) · 소변 · 대변 | 「베이비케어에 소변 기록」 |
| 6 | 수면 시작 | 「베이비케어에 잠들었어」 |
| 7 | 수면 종료 | 「베이비케어에 깼어」 |
| 8 | **종류 변수** — 11종 전부 | 「베이비케어에 ⟨종류⟩ 기록」 |

- 1~5 는 아이콘·제목이 따로 있어 단축어 앱·Spotlight 에서 눈에 보인다(자주 쓰는 것).
- 8 이 나머지(유축·이유식·간식·목욕·체온·투약)를 덮는다. 1~5 와 겹쳐도 무해 — 같은 인텐트·같은 판정.
- 문구 예산: 5×3 + 2×3 + 3×11 = **54**.

**기존 `RecordFeedingIntent` 는 v2.8.10 한 판 동안 남긴다.** 지우면 손님이 단축어 앱에 만들어 둔 것이 깨진다. 남기되 **내부는 새 판정에 위임**한다(문은 둘, 판정은 하나). App Shortcut 노출은 새 인텐트만. 다음 판에서 제거.

### 4.3 종류별 처리

`SiriPromptPolicy.required(for:)` 가 되물을 것을 돌려준다. 값은 **`ActivityDraftBuilder` 가 실제로 요구하는 것**과 일치해야 하고, 어긋나면 §7 게이트가 잡는다.

| 종류 | 되물음 | 비고 |
|---|---|---|
| 소변 · 대변 · 목욕 · 이유식 · 간식 | **없음** | 한마디로 즉시 저장 |
| 모유 | 없음 | 현행 유지(§9-A) |
| 분유 · 모유(병) · 유축 | **양 (ml)** | 1~500 · 현행 분유와 같은 방식 |
| 체온 | **온도 (°C)** | 34.0~43.0 |
| 투약 | **약 이름** | 못 들으면 이름 없이 저장(앱도 이름 없이 저장된다) |
| 수면 | — | §4.4 |

유축의 보관 방식(`pumpStorage`)은 시리에서 묻지 않는다 → `nil` = 냉장 가정(현행 계약).

### 4.4 수면 — 새 개념을 만들지 않는다

앱에는 이미 수면 타이머가 있다(`ActivityTimerManager` · Live Activity · 잠금화면 · 강제종료 복구). 시리는 **그것을 만진다.**

```
"잠들었어" → 타이머 시작 → "잘 자라고 기록했어요"
"깼어"     → 타이머 정지 → ActivityDraftBuilder → 저장 → "3시간 20분 잤어요"
```

**문제 하나 — 저장소가 둘이다.**

| 무엇 | 지금 어디에 |
|---|---|
| 타이머 상태(시작시각·타입) | `UserDefaults.standard` |
| 시리 컨텍스트(소유자·아기) | App Group `group.com.roacompany.allcare` |

시리는 앱 화면 없이 도는 별도 진입점이라 **둘이 같은 곳을 봐야 한다.**

→ **타이머 상태를 App Group 으로 옮긴다**(키도 `siri_timer_*` 접두 규약을 따른다). `resumeTimerIfNeeded()` 가 이미 "저장된 시작시각에서 복구"하는 구조라, 시리가 App Group 에 쓰면 앱이 열릴 때 그대로 이어받는다. 판정은 하나로 유지된다.
→ **이관 1회**: 기존 `UserDefaults.standard` 키에 값이 있으면 App Group 으로 옮긴다(업데이트 순간 자고 있던 아기의 타이머를 잃지 않기 위해).

**예외 처리**

| 상황 | 시리가 하는 말 |
|---|---|
| 이미 자는 중인데 "잠들었어" | "이미 자고 있다고 기록돼 있어요 (3시간째)" — 덮어쓰지 않는다 |
| 안 자는데 "깼어" | "자고 있다고 기록된 게 없어요" |
| 24시간 넘게 열려 있음 | 기존 `sleepTooLong` 문구 그대로 — 앱에서 시간을 고치게 |
| 다른 타입 타이머가 도는 중 | "지금 수유 타이머가 돌고 있어요" — 남의 타이머를 끄지 않는다 |

**Live Activity**: 시리에서 시작을 시도하되, 실패해도 타이머 상태는 남긴다(기록이 우선). 앱을 다음에 열 때 `reconcileWithRunningTimer` 가 붙인다. ⚠️ 백그라운드 실행에서 ActivityKit 이 뜨는지는 **기기 QA 항목**(§8).

### 4.5 저장 경로 — 변경 없음

```
시리 → SiriRecordPlanner (순수 판정)
     → ActivityDraftBuilder (저장 규칙 — 손 안 댐)
     → OfflineQueue.enqueueSave (큐 적재 = 저장 성공 계약)
     → AnalyticsService.logRecordSaved (source = .siri)
     → 인증 있을 때만 flush   ← #75 의 계약 그대로
```

**데이터 모델 변경 0.** 마이그레이션 0.

### 4.6 계측

`record_saved {record_type, source}` 가 전 종류에서 나간다(#76 에서 만든 것 재사용).

⚠️ **#76 은 아직 어떤 빌드에도 없다.** 지금 라이브(v2.8.9)에서 시리 기록은 GA4 에 **0건**으로 보인다 — "아무도 안 쓴다"가 아니다. v2.8.10 이 나가야 처음으로 세어진다.

## 5. 보안 · 격리 (현행 계약 유지)

- 저장 경로는 `SiriRecordContext` 가 준 **소유자 uid** 아래(가족 공유 아기 대응).
- 공백·누락 uid 거절(`users//babies/…` 방지).
- 로그아웃 시 스냅샷 삭제 — **수면 타이머 상태도 같이 지워야 한다**(새 항목).
  🔒 빠뜨리면 계정 전환 후 "깼어"가 **이전 계정 경로**에 쓴다(#39 결함군).

  ⚠️ 다만 `AppState.resetUserScopedState` 에 **한 줄 더 적는 방식으로 하지 않는다.**
  그 함수는 지울 것을 **이름으로 나열**하는 자리다(30줄 넘는 목록 + `UserDefaults` 키 문자열들).
  같은 모양의 결함을 이미 세 번 겪었다 — 나열하면 나중에 생긴 것이 조용히 빠진다.

  → **접두 규약**을 쓴다. 시리가 읽는 사용자 범위 값은 전부 `siri_` 로 시작하고
  (`SiriRecordContextStore` 가 이미 그렇다), 지우는 쪽은 **접두가 붙은 키를 싹 지운다**:

  ```swift
  for key in defaults.dictionaryRepresentation().keys where key.hasPrefix("siri_") {
      defaults.removeObject(forKey: key)
  }
  ```

  이러면 **지울 목록이 아예 없다** — 나중에 `siri_` 키가 하나 더 생겨도 자동으로 지워진다.
  `resetUserScopedState` 에는 지금 있는 **한 줄이 그대로** 남는다(호출 대상 이름만 바뀐다).
  게이트도 키 이름을 적지 않는다 — 아무 `siri_` 키나 하나 넣고 `clearAll()` 뒤에 비었나로 잰다.
- 인증 없을 때 `flush()` 금지(큐 5회 실패 폐기 방어) — 현행 유지.

## 8. 기기 QA (PO — 시뮬레이터로는 못 잼)

시리는 시뮬레이터에서 제대로 돌지 않는다. #75 와 같이 **실기기**에서 잰다.

1. 「베이비케어에 소변 기록」 — 앱 **미실행** 상태에서 저장되나
2. 「베이비케어에 유축 기록」 → 되묻기 → 양 말하기 → 저장되나
3. 「베이비케어에 체온 기록」 → 「37도 5」 같은 소수 인식
4. **「잠들었어」 → 잠금화면에 뜨나 → 「깼어」 → 시간이 맞나**
5. 앱을 열었을 때 타이머 배너가 이어지나 (App Group 이관 확인)
6. 업데이트 직전에 타이머가 돌고 있었다면 살아남나 (1회 마이그레이션)
7. 타임라인 표기 — 종류·색·라벨이 앱에서 한 것과 같나

## 9. 열린 질문 (PO)

**A. 모유 수유도 타이머로 바꿀까?**
앱에서 모유는 타이머(시간이 핵심)인데 **시리는 즉시 저장**한다 — 이미 갈라져 있고, v2.8.9 로 손님에게 나갔다.
- 그대로 두기: 밤중 수유는 "먹였다"가 핵심이고 앱도 시간 없이 저장된다. 나간 동작을 안 바꾼다.
- 수면처럼 바꾸기: 「젖 물렸어」/「다 먹었어」. 일관되지만 **라이브 동작이 바뀐다.**

→ **기본은 "그대로 두기"** 로 잡고 진행합니다. 바꾸라 하시면 반영합니다.

**B. 투약 약 이름을 되물을까?**
약 이름은 자유 발화라 시리 인식이 부정확하다. 지금 설계는 "묻되, 못 들으면 이름 없이 저장". 아예 안 묻는 쪽도 가능하다.

→ **기본은 "묻되 못 들으면 저장"** 으로 진행합니다.
