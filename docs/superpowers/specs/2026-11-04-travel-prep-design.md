# 베이비케어 「여행 준비」 — 첫 판 설계 (2026-11-04)

## 1. 왜 · 무엇을 · 정한 것

- **PO 결정(11/4)**: 아이 동반 여행 기능을 따로 앱이 아니라 **베이비케어 안에** 넣는다.
  첫 판 = **출발 전 TestFlight**, **기능만**, **빈 상태**에서 PO 가 여행 만들기부터 직접 넣는다(예시·이번 여행 값을 미리 넣지 않음).
- **차별점(PO 11/3)**: 유기적인 연결(예약·항공편·하루 일정이 이어짐) + 수유실 같은 아기 맞춤 정보.
- **기획서 원칙 그대로**: 아이에서 출발 · 근거를 붙여 안내(확인 안 된 건 안내하지 않음) · 부모 둘이 함께 · 장소 추천이 아니라 시설 안내.
- **성공 기준**: PO 가족이 실제 해외여행 하나를 이 판으로 준비하고 다녀온다. 막힌 점은 기존 기록장(아티팩트)에 적는다.
- 같은 앱이 되면서 **아이 정보 연동이 필요 없어진다** — 아이 기록은 앱 안의 기록을 바로 읽는다(연동 명세의 두 앱 전달·동의 화면은 이 판에 없음).

## 3. 화면 자리와 흐름

- **들어가는 곳 둘**: 설정 「바로가기」 절에 「여행 준비」 줄(할 일·루틴 줄과 같은 방식 `NavigationLink`) · 홈에는 **다가오는(또는 진행 중인) 여행이 있을 때만** 카드 한 장(`tripCardIfNeeded` — 없으면 `EmptyView`). 탭은 늘리지 않는다.
- **밀어 들어가는 화면에는 자기 `NavigationStack` 을 두지 않는다**(PR #9 규칙). 입력은 시트(시트는 자기 스택을 가짐 — AddTodoView 선례).
- 흐름: 여행 목록(비어 있으면 「여행 만들기」) → 여행 만들기 시트 → 여행 화면.
- **여행 화면** = 머리(도시 · 날짜 · 출발까지 며칠) + 네 칸 고르기 **할 일 · 일정 · 예약 · 규칙**(시안의 「여행 안」 그대로).
  - 할 일: 목록(권장일 순) · 줄 = 체크 · 제목 · 마감 줄(편마다) · D-day · 담당 칩 · 「우리 아이 해당」 표시 · 누르면 규칙 카드.
  - 일정: 날짜 고르기 → 그날 시간표(예약 · 이동 · 리듬 · 겹침 · 공항 수유실 링크).
  - 예약: 항공편 · 숙소 · 렌터카 목록 + 「+」 · 줄마다 무료 취소 기한 · 「구글지도에서 열기」 · 숙소/렌터카 사이 「길 보기」와 이동 시간 넣기.
  - 규칙: 이 여행에 걸리는 규칙 카드 + 출발·도착 공항 시설 안내.
- **옷은 옆 화면에서**: 목록 = `TodoView`·`RoutineView` 처럼 `List(.insetGrouped)` + `AppColors` + 「+」 시트(`Form`) · 홈 카드 = `TodayBandCard`/`PartnerInvitePromoCard` 모양 · 빈 화면 = `EmptyStateView`. 시안의 파란 옷은 쓰지 않는다(베이비케어 분홍 · 시스템 글꼴). 문구는 최근 기능처럼 한국어 그대로(조사 = `KoreanParticle`).

## 4. 저장

원칙: **사람이 넣은 것만 저장**한다(여행 · 예약 · 할 일의 완료/담당 · 이동 시간). 할 일 목록·마감·하루 일정은 **그때그때 계산**한다(순수 함수) — 규칙을 고치면 다음 실행에서 바로 반영되고, 저장 모양이 규칙에 묶이지 않는다.

- 경로 = `users/{소유자}/babies/{아기}/trips/{tripId}` — 문서 하나에 예약·할 일 상태·이동을 **배열로 품는다**. 이 깊이는 지금 `firestore.rules` 가 소유자·공유 보호자 둘 다 이미 허용한다(아기 아래 `/{subcollection}/{docId}` 한 단계) → **규칙 변경·배포 없음**. 한 단계 더 내려가는 하위 컬렉션은 만들지 않는다(규칙에 안 걸림).
- 5단계: `FirestoreCollections.trips` · `FirestoreService+Trip.swift` · `TripFirestoreProviding: Sendable` · `extension FirestoreService: TripFirestoreProviding {}` · `BabyCareTests/MockTripFirestore.swift`.
- 모델(전부 `Identifiable, Codable, Hashable` · 새 필드 optional · 종류 enum 은 `unknown` 센티넬 — 읽기만, 저장하면 throw):
  - `Trip` — id · babyId · countryCode("JP") · city · startDay · endDay("yyyy-MM-dd") · bookings · taskStates · moves · createdBy · createdAt · updatedAt · schemaVersion 1
  - `TripBooking` — id · kind(flight/hotel/rentalCar/unknown) · 항공편(airline · flightNumber · fromAirport · toAirport · departAt · arriveAt) · 숙소(name · address · checkInAt · checkOutAt) · 렌터카(company · pickupPlace · pickupAt · returnPlace · returnAt) · freeCancelUntil
  - `TripTaskState` — taskId · isDone · doneAt · doneBy · assignee(mother/father/both/none/unknown)
  - `TripMove` — id · startAt · minutes · fromLabel · toLabel
- 읽기 실패한 문서를 `decodeDocuments` 가 조용히 버리므로, 여행 하나가 통째로 사라지지 않게 **모르는 값은 센티넬로 읽는다**(저장 거부).
- 데이터는 지우지 않는다 — 「여행 지우기」는 사용자가 누를 때만, 확인 한 번 뒤.

## 5. 규칙·마감 엔진

순수 함수 `TripTaskEngine.tasks(trip:bookings:child:catalog:now:)` → 할 일 목록. 할 일 id = 규칙 키 + 예약 id(안정 id — 완료 체크가 다시 계산해도 붙어 있게).

| 키 | 조건 | 할 일 · 마감 | 근거 |

| bassinet | 대한항공 편 · 아기 키 75cm·체중 11kg 이하(최근 성장 기록, 없으면 「키·체중을 넣으면 알려 드려요」) | 배시넷 신청 · 편마다 출발 48시간 전 | 대한항공: 아이와 함께 여행 |

- 11/4 확인: 대한항공 배시넷(국제선 · 출발 48시간 전 · 체중 11kg 이하 · 신장 75cm 이하)과 유아식(출발 24시간 전)은 공식 「유아 동반 승객」 쪽의 **검색 요약으로 확인**(공식 사이트 직접 접속은 403 · 우회 안 함). 앱 안 출처 줄에 그렇게 적는다.
- 국제운전면허 · 옆자리 맞추기 · Visit Japan Web 은 출처를 확인한 뒤 넣는다(확인 전엔 안 넣음).
- 대한항공이 아닌 항공사는 「이 항공사 규칙은 아직 없어요」 — 없는 규칙을 지어내지 않는다.

### 할 일 한 줄의 단위(11/4 캔버스 할 일 검토 ①② — PO 「네」로 정한 것)
- **배시넷·유아식 = 여행에 한 줄씩**, 그 줄에 편마다 마감 줄을 쌓는다(가는 편 · 오는 편). id = `bassinet` / `infant_meal` — 편을 고치거나 더해도 체크가 풀리지 않는다. 체크는 줄 하나(편별 체크 없음).
- **무료 취소 기한 = 그 예약에서 생긴 아기 확인 일의 마감**(실제 준비 페이지 방식): 숙소 → 「숙소에 아기침대 요청」 · 렌터카 → 「렌터카 카시트 확인」. 「무료 취소 기한」만 따로 한 줄을 만들지 않는다. 기한을 안 넣었으면 그 일은 마감 없음. id = `hotel_crib-<예약id>` / `car_seat-<예약id>`.
- 이유식 = `solids_quarantine` 한 줄 · 기내 반입은 할 일 없이 규칙 카드만.
- 알림 수 = 마감 줄 수 × 2(여행 하나에 많아야 십수 개 — 상한 64 안).

### 순서와 표시(PO 11/4 결정)
- 목록 순서 = **권장일**. 권장일(판단): 마감 있는 일 = 마감 7일 전 · 마감 없는 준비 = 출발 7일 전 · 권장일이 오늘보다 앞이면 오늘.
- D-day 와 빨강은 **마감에만** · 빨강은 마감 3일 전부터 · 권장일은 회색 「○○쯤 하면 좋아요」 — 지나도 빨개지지 않음.

## 6. 하루 일정

- 아기 리듬 = 7일 기록으로 계산하는 순수 함수 `BabyRhythmSummary.build(activities:window:calendar:)`. 계산 기준은 「베이비케어 연동 명세」(10/17) 그대로 옮긴다 — 앱에 세 번째 기준을 만들지 않는다:
  - **낮잠** = 06~18시에 시작 · 15분 이상 · 19시 전에 끝난 잠(06~18 경계 = `SleepAnalysisService` 와 같음). 묶기: 시각 순으로 늘어놓고 앞 낮잠보다 시작이 90분 넘게 늦거나, 같은 날 낮잠이 이미 그 묶음에 있거나, 묶음 폭이 2시간을 넘게 되면 새 묶음. share = 그 묶음에 낮잠이 있는 날 ÷ 수면 기록이 있는 날 · 0.3 미만 묶음은 버림 · 시작 = 묶음 시작 시각 중앙값 · 길이 = 기록마다 (끝 − 시작) 중앙값.
  - **밤잠 시작** = 밤마다 18시~06시 전에 시작한 잠 가운데 1시간 넘게 잔 첫 잠의 시작, 그 중앙값.
  - **기상** = 18시~06시 전에 시작한 잠을 끝난 날짜로 묶고, 04~10시에 끝난 것 중 가장 늦은 끝 시각의 중앙값(끝 시각 없는 기록은 뺌).
  - **낮 수유 간격** = 모유·병수유 기록만 · 그날 기상부터 밤잠 전까지(모르면 06~22시) 시작한 수유끼리 간격의 중앙값 · 6시간 넘는 간격은 뺌 · 간격 4개 미만이면 없음(그 칸은 비워 두고 「기록이 더 있으면 알려 드려요」).
  - **이유식 시각** = 이유식 기록 시각을 낮잠과 같은 규칙으로 묶어 묶음별 중앙 시각과 share.
  - **고기** = 이유식 음식 이름에 고기 낱말(소고기 · 닭고기부터 · 물고기 같은 말은 거름)이 하나라도 있으면 있음 · 모든 이유식에 이름이 있고 고기 낱말이 없으면 없음 · 이름 없는 이유식이 있으면 모름.
  - **카시트 낮잠** = 15분 이상 낮잠 중 잠든 곳이 카시트(`sleepMethod == .carSeat`)인 수.
  - 자정을 넘긴 잠은 `ActivityDayAttribution` 규칙대로(밤 하나는 한 번만 셈).
- **7일 창(내 판단)**: 출발 전엔 「오늘까지 거꾸로 7일」 · 출발일부터는 「출발 전 7일」로 고정 — 여행 중 흐트러진 날이 섞여 일정이 흔들리지 않게. 창 안에 기록 있는 날이 4일 미만이면 「기록이 적어 대략이에요」.
- 날짜마다 항목 = 그날 예약 시각(출발·도착·인수·반납·체크인·체크아웃) + 직접 넣은 이동(시작·분) + 리듬.
- 수유는 깬 시각부터 평소 간격마다 놓고, 낮잠과 겹치면 깬 뒤로(판단). 이유식은 평소 시각.
- 겹침 표시: 낮잠 ↔ 비행·운전 · 밤잠 시작 20분 전~1시간 뒤 ↔ 운전·체크인 · 비행·운전 중 수유는 「비행 중이에요 / 운전 중이에요」.
- 공항에 있는 시각의 항목에는 그 공항 수유실 안내로 가는 링크.
- 기록이 적으면(7일 중 기록 있는 날이 적으면) 「기록이 적어 대략이에요」를 붙이고, 없으면 리듬 없이 예약만 보여 준다.
- 일본과 한국은 시차가 없어(둘 다 UTC+9) 이 판은 시각을 현지 시각 하나로 다룬다. 시차 있는 나라는 다음 판.

## 7. 공항 시설 안내(이 판의 데이터)

## 8. 지도

구글지도 주소 방식(Maps URLs · 키 없음): 장소 = `https://www.google.com/maps/search/?api=1&query=<주소>` · 길 = `https://www.google.com/maps/dir/?api=1&origin=<출발>&destination=<도착>&travelmode=driving`.

## 9. 알림

- 기존 `NotificationService`(폰 안 알림) 에 여행 마감 알림을 더한다: 마감 3일 전·전날 09:00 · id = `trip-<tripId>-<taskId>-d3` / `-d1`.
- 계산은 순수 함수(`TripReminderPlanner` — 무엇을 언제)로 하고, 예약·완료가 바뀌면 `trip-<tripId>-` 로 시작하는 것을 지우고 다시 건다. 완료한 일·지난 시각은 걸지 않는다.
- 화면은 알림 서비스를 직접 부르지 않는다(arch R1) — 뷰모델이 부른다. 권한은 지금처럼 홈에서 받는다. iOS 의 대기 알림 상한(64)을 넘지 않게 여행 하나에 마감 수 × 2 만.

## 10. 같이 쓰기

- 여행은 아기 아래에 저장되므로 **이미 공유받은 보호자(배우자)가 그대로 보고 고친다**(경로 = `babyVM.dataUserId(currentUserId:)` · `currentUserId` 가 nil 이면 먼저 멈춤 — 로그아웃 뒤 소유자 경로가 살아 있는 함정).
- 담당은 사람 계정이 아니라 **엄마 · 아빠 · 함께 · 담당 없음** 넷 중에서 고른다(관계 값이 보호자마다 흩어져 있어 계정과 잇지 않는다). 체크한 사람(`doneBy`)은 계정 id 로 남긴다.
- ⚠️ 공유 규칙 구멍(초대 정보를 누구나 읽음)은 이 판의 범위가 아니다 — 여행 문서도 같은 규칙을 탄다(따로 고칠 일).

## 12-0. 시간대
