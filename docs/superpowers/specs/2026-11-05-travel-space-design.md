## 2. 여행 공간 — 홈 · 일정 · 예약 · 준비 (캔버스 Version 84 · PO 2026-11-06 「네 시안.」로 짜임 바꿈)

PO 원문: *「제발 여행앱인데 아이특화된 여행앱인거야... 제발 정상적으로... 제발..」* → 바탕은 보통 여행 앱(일정 · 예약), 그 위에 아이(잠·수유 겹침 · 준비할 일 · 규칙).

- 전체 화면 · 자기 아래 바 넷: 홈 · 일정 · 예약 · 준비. 왼쪽 아래 동그란 「←」로 베이비케어에 돌아간다(§7). 칸마다 NavigationStack 하나.
- 여행 고르기: 홈 머리의 도시 이름(⌄) 메뉴 = 여행 목록 · 새 여행 만들기 · 여행 삭제(확인 받음). 처음 열 때는 다가오는 여행(TripListViewModel.nextTrip), 없으면 가장 최근.
- 여행이 없으면 네 칸 모두 「여행 만들기」 빈 화면(시안 「처음 열었을 때」의 말 · 예시 값은 넣지 않는다 — 11/4 PO 「비워놓고」).
- 여행을 바꾸면 준비 칸 거르기·칸 · 일정 칸 고른 날 · 홈에서 밀어 연 화면을 처음으로.

### 홈 (시안 Main · Home-Flight)
- 머리: 도시(⌄) · 오른쪽 회색 「수정」(여행 수정 시트 · §10) · 칩(출발 전 「D-n」 · 출발일 「오늘 출발」 · 여행 중 「여행 n일째」 · 다녀온 뒤 「다녀왔어요」) + 「5.10(월)–5.14(금) · 4박 5일」.
- 오늘 떠나는 편이 있으면 항공편 칸(운항 정보 · 늦어진 시간으로 다시 본 일 · §5). 다른 날 편은 아래 「다음 일정」 줄에 있다.
- 다음 일정: 출발 전 = 첫날 「다음 일정 · 1일차 5.10(월)」 · 여행 중 = 오늘 「오늘 일정 · n일차 …」 · 다녀온 뒤 = 칸 없음. 줄 = 그날 예약·이동만 5줄까지(아기 리듬 줄은 일정 칸에만) · 아이 칩 = 비행·이동이 낮잠과 겹침 / 밤잠 시각이 비행·이동 중 / 체크인·도착·인수·이동이 밤잠 20분 전~60분 뒤(일정 칸과 같은 기준). 「일정 전체」 → 일정 칸 그날.
- 할 일: 출발 전 「출발 전 할 일」 · 출발일부터 「남은 할 일」 — 다음 할 일 + 이번 주, 앞 3개 · 「n개」(안 끝난 수) → 준비 칸 할 일(전체).
- 아이: 출발일 월령 · 낮잠 · 밤잠 · 「최근 7일 기록으로 계산했어요」 · 「아이 정보」 → 아이 화면(홈에서 밀어 연다).

### 일정 (시안 Day-Plan)
- 머리 「일정」 + 「오사카·교토 · 5.10(월)–5.14(금)」(일정·예약·준비가 같은 머리) · 날짜 칸 「1일차 / 5.10(월)」 · 그날 시간표(예약 · 이동 · 아기 리듬 · 겹침 · 공항 수유실) · 「+ 일정 추가」.

### 예약 (시안 Trip-Bookings)
- 머리 「예약」 · 예약 추가(Babycare AI로 추가 · + 항공편 · + 숙소 · + 렌터카) · 가는 날 시간표 · 다른 날 예약 · 일정.

### 준비 (시안 Trip-Todo · Trip-Rules)
- 머리 「준비」 · 밑줄 칸 할 일 | 규칙.
- 할 일: 담당으로 거르기(전체 · 엄마 · 아빠 · 함께 · 담당 없음 — 숫자는 안 끝난 일) · 주별 목록 · 맨 아래 알림(마감 3일 전 · 마감 전날 켜고 끄기 — 이 폰에만 · 사용자 기록이 아니라 기기 설정). 알림은 옛 가족 칸에 있던 것 — Version 84 시안에서 빠졌던 것을 되살려 여기로 옮겼다.
- 할 일 꼬리글: 「마감은 규칙과 넣은 예약으로 계산해요」(메일 연동이 없다).
- 규칙: 이 여행의 규칙 · 공항 시설 안내.

### 아이 (시안 Child)
- 홈 「아이 정보」로 밀어 연다 · 시스템 위 막대의 뒤로 「‹ 홈」(쓸어서 뒤로 가기 됨) · 아래 바는 그대로(홈 칸).
- 생년월일 · 출발일 월령 / 키·체중과 잰 날 / 먹는 것(이유식 여부 · 고기 · 낮 수유 간격) / 낮잠(시작·길이) · 카시트에서 잔 낮잠 / 밤잠·기상.
- 「베이비케어 기록」: 최근 7일 기록으로 계산 · 기록 있는 날 수 · 출발일부터는 출발 전 7일로 고정.
- 시안의 「고치기」는 뺀다(아기 정보는 베이비케어 설정에서).

### 짜임 바꾸며 없앤 것 (11/6)
- 가족 칸 — 담당 정하기는 준비 칸 담당 칩 · 담당별 수는 담당 칩 숫자 · 알림은 준비 칸 할 일 아래. 사람별 목록 · 항공편 지연 알림 · 「엄마가 할 일을 끝냈을 때」는 원래 없었다(공유받은 사람을 읽는 길 · 서버 알림이 없다).
- 여행 칸(할 일·일정·예약·규칙 네 밑줄 칸) — 일정·예약은 아래 바 칸으로, 할 일·규칙은 준비 칸으로.
- 홈 「다음 할 일」 큰 카드(완료로 표시 · 항공사에서 신청하기) — 시안에 없다. 항공사 신청 주소는 규칙 카드 출처에 있다.
- 설정의 옛 여행 목록·여행 화면(부르는 곳이 없던 화면)은 지웠다.

## 5. 연동 — 항공편 실시간 · 이동 시간 (PO 2026-11-05 추가)

PO 원문: *「구글지도랑 항공편싱시간 api 연결했어?」* → *「전부 다 해야지 뭔소리야.... 그리고 파킹24에 썼던거 있으니까 그거 그대로 써.」* → *「우리 개발언어 뭐야? 구글지도 api 신청하고자 함.」*

| 무엇 | 어디서 | 실측(2026-11-05) |
|---|---|---|
| 항공편 실시간 | 공공데이터포털 「인천국제공항공사_여객편 운항현황(다국어)」 · **파킹24 와 같은 개발계정 키** | KE725 출발 목록 정상(resultCode 00) · 없는 편 = 빈 배열 · 공항 이름에 「오사카/ 간사이」처럼 띄어쓰기 · 소문자 편명도 받는다 |
| 이동 시간 | **구글 키가 앱에 있으면 구글 Routes API, 없으면 애플 지도**(키·결제 없음) | 파킹24 에는 구글 키가 없다(네이버 지도 키 · 네이버 길찾기는 국내만) · 애플 지도에 한글 「간사이공항」 → **리무진 사무소**를 잡아 교토역 44분(틀림) · 「関西国際空港」 → 76분 |

- 인천공항 정보는 **인천을 오가는 편만 · 당일치만** 준다 → 그날이 아닌 편은 「○.○(요일) 당일에 보여요」. 인천에서 뜨면 출발 목록, 인천에 내리면 도착 목록.
- 지연 = 공항 표기 「지연」 또는 예정보다 **15분 이상**(미국 교통통계국 정시 기준과 같은 선). 결항·회항은 빨강.
- 늦어진 가는 편 → **「늦어진 시간으로 다시 봤어요」**(시안 Home-Flight): 도착 = 예약 도착 + 늦어진 시간 · 렌터카 인수보다 늦으면 알림 문구 · 그날 숙소까지 **빨라야** 몇 시(입국·짐 찾기 시간은 모른다 → 더하지 않는다) · 밤잠을 넘기면 그 줄. ⛔ 할 일을 새로 저장하지 않는다(저장 모양 그대로).
- 지도에 넘기는 이름은 `TripRoutePlace.query` 하나로: 공항은 공식 이름(関西国際空港 …) · 숙소 이름은 그 숙소 주소. 애플 지도는 **찾은 곳 이름을 화면에 같이** 보인다(틀린 곳을 잡으면 손님이 안다).

## 11. 장소 검색 — 찾기 화면을 따로 연다 (PO 2026-11-06 「네.」 · 캔버스 Search-Move · Search-Hotel)

PO 원문(빌드 112 기기): *「여기서 장소찾아서 검색하는기능이 없는듯」* · *「왜 제대로 검증도 안하고 테스트플라이트에 올렸나요?」*
뿌리: 후보를 칸 바로 밑에 그려서 아래쪽 칸은 후보 전부가 자판 밑이었고, 흐름 시험은 여행이 없어 넣는 창에 한 번도 못 갔다.

- **넣는 창엔 글자 칸이 없다**: 일정·렌터카 = 그 여행의 곳 칩 + 돋보기 「다른 곳 찾기」 · 숙소 = 회색 「숙소 검색」 칸. 누르면 찾기 화면(`TripPlaceSearchSheet`). 고른 곳은 칩으로 들어간다(`TripEntryChoices.chips`). 시안에 없던 주소 칸은 뺐다.
- **찾기 화면**: 맨 위 검색 칸 · 바로 밑 후보 · 칸이 어디 있든 같은 화면이라 후보가 늘 자판 위에 온다. 자판 검색 키 = 자판 내리기 · ✕ = 비우기 · 다시 열면 숙소는 고른 이름으로 열린다.
- **줄 순서**(`TripPlaceSearchRows`): ① 「직접 입력」(지도가 못 찾는 곳) ② 공항 ③ 지도 후보(지도가 낸 순서 그대로).
- **공항은 앱이 먼저 낸다**: 11/6 실측 「간사이」에 지도가 대학·병원만 내고 공항이 없었다 → `TripRoutePlace.airports` 에서 찾는다. 한 글자는 끌어오지 않는다. 숙소 찾기엔 안 나온다.
- **숙소 찾기는 숙박 시설만**: 11/6 실측 「교토역」에 주차장·술집이 호텔보다 먼저 나왔다 → 지도에 숙박 시설만 요청(`PlaceSearchModel(lodgingOnly:)`). 지도에 없는 숙소는 「직접 입력」.
- **숙소를 다른 이름으로 직접 입력하면 옛 주소를 지운다**: 주소 칸이 없어 고칠 길이 없고, 길찾기는 주소를 먼저 봐서 옛 숙소로 간다(`TripBookingForm.pickingHotel`). 같은 이름을 다시 누른 것뿐이면 주소를 지킨다.
- **주소는 숙소만 받는다**: 일정·렌터카는 이름만 쓰므로 지도에 다시 묻지 않는다(느린 망에서 기다리지 않게). 숙소는 받아 오는 동안 그 줄에 도는 표시 · 다른 줄을 누르거나 취소하면 늦은 답은 버린다. 지도가 답을 못 하면 이름만 넣는다(우편번호·시 이름을 주소로 넣지 않는다).
- **고른 칩을 다시 누르면 비운다**: 렌터카 장소는 안 넣어도 되는 칸이고, 글자 칸이 없어 비울 길이 이것뿐이다.
- **긴 이름 칩**은 줄 폭까지만 — 말줄임으로 줄어든다(`TravelWrapLayout`).
- **게이트**: `BabyCareUITests/TripPlaceSearchFlowTests` — `UI_TESTING_WITH_TRIP`(`UITestTripFirestore` · `#if DEBUG` · 출시 빌드 제외)로 시험 여행을 넣고 눌러서 넣는 창까지 가, 실제 자판 위치로 잰다. CI 는 안 태우므로 TF 전에 직접 돌린다.
- 같이 고친 것:
  - 여행 수정에서 「도시 추가」로 칸이 늘면 달력(LazyVGrid)이 화면 밖으로 밀려 높이를 짐작하고 「여행 기간」이 회색 띠 위로 올라탔다 → 달력을 `Grid` 로.
  - 예약 칸 숙소·렌터카 줄의 제목을 누르면 수정 대신 구글지도가 열렸다(눌러 보니 제목·링크 사이까지 지도로 끌려갔다 · 줄 오른쪽 빈 곳과 시각은 수정) → 지도 링크는 제스처로 제 자리만 받고, 제목 칸도 눌리는 곳으로.
  - 일정 소요 시간: 장소를 바꾼 뒤 늦게 온 앞 장소의 답이 새 값을 덮지 않게 버린다.
