# 일정표는 계산만 하고, 모르는 시각은 지어 넣지 않는다

여행 일정은 예약에서 그때그때 계산하고, 저장하는 것은 사람이 넣은 사실뿐이다. 모르는 시각은 시각 미정으로 두고 일정표가 「확인할 것」으로 묻는다.

2026-11-06 까지 앱은 새 예약에 14:00, 오는 편에 00:00 을 넣었다. 칸은 전부 동작했지만 1일차가 「체크인 → 렌터카 → 인천 출발」이 되고 오는 편 마감이 00:00 으로 계산됐다. 지어낸 값이 일정과 마감으로 번져서, 사람이 틀린 줄도 모른 채 믿게 된다.

## Considered Options

- **시각을 꼭 고르게 막기:** 일정표는 단순해진다. 하지만 사실 모르는 시각(체크인 몇 시에 닿을지, 렌터카 정확한 인수 시각)을 사람에게 지어내게 만든다. 앱이 지어내던 것을 사람에게 떠넘길 뿐이다.
- **그럴듯한 기본값(체크인 15:00):** 시안 예시 값이지만 사실이 아니다. 22:00 에 닿는 날에도 15:00 이 찍혀 일정이 틀어진다.

## Consequences

일시는 날짜만으로도 성립해야 한다. 표준을 따른다: iCalendar 는 날짜만 있는 값과 시각까지 있는 값을 구분한다(RFC 5545 §3.3.4). 조사 = `docs/superpowers/research/2026-11-06-trip-time-sources.md`.
